# ggit

多项目 Git **只读**查看工具（Windows，Python + PySide6）。常驻后台，`Alt+G` 随时调出。

- 顶部：每个项目一个 200 宽的大标签（快捷键序号 + 项目名 + 状态圆点），鼠标悬停显示分支和同步状态
- **两种工作模式**（`Alt+F` 切换）：
  - **git 模式**：左侧是 git 树（“更改”列表 + 提交图，点提交就地展开它修改的文件），右侧是文档标签页 + diff（上下合并 / 左右对照）
  - **file 模式**：左侧是以项目根目录为起点的文件树，点文件在右侧预览文本 / 代码，可同时打开多个文件

## 运行

需要：Python 3.10+（PySide6 6.11 的要求），已安装 Git 且 `git` 在 PATH 中。

```bat
pip install -r requirements.txt
python -m ggit
```

也可以直接双击 `ggit.pyw`（不会弹出黑色控制台窗口）。

## 后台常驻

- 点窗口右上角的 × **只是隐藏到托盘**，程序继续在后台运行；真正退出：托盘图标右键 → 退出，或 `Ctrl+Q`。
- **全局热键 `Alt+G`**：窗口在前台就隐藏；否则显示到所有窗口最前面。（热键被别的程序占用时，状态栏会提示。）
- 再次启动 ggit 只会把已经在运行的那个窗口调出来（不会开第二个）。按 Windows 用户区分：同一台电脑上的不同用户各开各的。
- 开机自启：把快捷方式放进启动文件夹，目标后面加 `--background`（启动后不显示窗口）。
- 窗口标题是 `ggit - <当前项目名>`。

## 快捷键

| 操作 | 快捷键 / 鼠标 |
|---|---|
| 显示到最前面 / 隐藏到后台（全局） | `Alt+G` |
| 切换到第 1–9 / 第 10 个项目 | `Ctrl+1` … `Ctrl+9` / `Ctrl+0`，或点击顶部标签 |
| 上一个 / 下一个项目 | `Ctrl+Shift+Tab` / `Ctrl+Tab` |
| 搜索切换项目（含第 10 个之后的） | `Ctrl+P`，或顶部“全部项目 ▾” |
| 刷新当前项目 | `F5` |
| 切换工作模式（git ⇄ file） | `Alt+F` |
| 切换 diff 模式（上下合并 ⇄ 左右对照） | `Alt+D`（或 diff 标题栏的按钮） |
| 上一处 / 下一处改动 | `F3` / `F4`（或标题栏的 ↑ ↓） |
| 关闭当前文档 / 全部文档 | `Ctrl+W` / `Ctrl+Shift+W`（标签上的 ×、鼠标中键也可以） |
| 上一个 / 下一个文档 | `Ctrl+PgUp` / `Ctrl+PgDown` |
| 分支列表（所有本地 / 远端分支） | `Ctrl+B`，或点左上角的分支名 |
| 搜索文件：git 模式查看它的历史，file 模式打开预览 | `Ctrl+F`（git 模式也可在文件上右键 → 查看文件历史） |
| 展开 / 收起提交的文件 | 点击提交行；`→` 展开、`←` 收起、`Enter` 切换（在文件行上按 `Enter` = 打开它） |
| 添加项目 | `Ctrl+O` |
| 当前项目左移 / 右移 | `Alt+Shift+←` / `Alt+Shift+→`，或用鼠标拖动当前项目的标签 |
| 退出文件历史，回到提交图 | `Esc` |
| 刷新全部项目的状态标记 | `Ctrl+Shift+R` |
| 放大 / 缩小 / 重置全局字体（7–24 pt，默认 9 pt） | `Ctrl+=` (或 `Ctrl++`) / `Ctrl+-` / `Ctrl+Shift+0` |

顶部标签：左边的数字是 `Ctrl+数字` 的序号；右边**黄色圆点** = 有未提交改动，**红色圆点** = 读取项目状态失败。
鼠标悬停在标签上，会显示路径、分支、是否有未提交改动、领先 / 落后远端几个提交。

## 使用说明

- **提交图**：默认显示**所有本地分支、远端分支和标签**（按提交时间排序，最近动过的分支在最上面）。
  右上角下拉框可以切到“当前分支”（只看当前分支及其远端对应分支）。到底部会自动加载更多（每次 500 条）。
  分支名、远端分支（☁ origin/xxx）、标签显示在提交行右侧；空心圆是当前所在位置。
- **分支列表**：点左上角的分支名（或 `Ctrl+B`），列出所有本地分支和远端分支——当前分支排第一，其余按最近提交排序，
  并显示每个分支领先 / 落后上游多少、最近一次提交。选一个分支，提交图就只显示它的历史；
  右上角下拉框里选“全部分支”回到全貌。状态行右边会显示“本地 N · 远端 M 个分支”，方便核对。
- **文件清单**：点提交行展开它修改的文件（分支线继续穿过文件行），再点一次收起；**点文件在右侧新开一个标签**。
  合并提交相对**第一个父提交**。方向键只移动选中，不会一路开出一堆标签，按 `Enter` 才打开。
- **文档标签页**：点一个文件就**新开一个标签**，已经开着的文件再点只会切换过去，**旧的标签不会被关掉**。
  关闭：标签上的 ×、鼠标中键、`Ctrl+W`；右键标签有“关闭其他 / 关闭全部”；标签可以拖动换顺序。
  git 模式和 file 模式、每个项目都有自己的一套标签页，切换项目或模式时各自保留。
- **file 模式**：左侧文件树以项目根目录为起点（不显示 `.git`），点目录展开 / 收起，点文件在右侧预览，
  带行号；UTF-8 / GBK 自动识别（“查看 → 文件编码”可强制指定）；超过 3MB 只显示开头，二进制文件不预览。
  打开着的文件会跟着磁盘上的修改自动更新（窗口重新激活或按 `F5` 时）。
- **更改**：工作区和暂存区里未提交的文件（`M` 修改、`A` 新增、`D` 删除、`R` 重命名、`U` 未跟踪、`C` 冲突）。
  超过 5000 个时只列出按路径排序后的前 5000 个，标题上会写明总数。
- **搜索文件（`Ctrl+F`）**：只列出 Git 管理的文件；file 模式下再加上未被 `.gitignore` 忽略的新文件，
  `node_modules`、`build` 这类被忽略的目录不会出现在列表里（文件树里照样可以浏览）。
  多个关键字用空格分开；最多列出 300 条，匹配更多时下方会提示总数，再输入一些关键字就能缩小范围。
- **分支很多时**：提交图的分支线超过 10 条会自动压窄列宽，每条线仍然单独占一列；超过 28 条才挤在最右一列。
- **diff 两种模式**
  - 上下合并：只显示改动处及前后 3 行，红底 = 删除，绿底 = 新增。
  - 左右对照：左边修改前、右边修改后，显示整个文件；改动块两侧逐行对齐，短的一侧补灰色空行，两边同步滚动。
  - 右侧加宽的滚动条上用**红 / 绿色块**标出每一处改动的位置（红绿各半 = 这一处既有删除又有新增）；
    点色块直接跳过去，点空白处跳到对应位置。
  - 特别大的差异（超过 10MB 或 3 万行；未跟踪的新文件超过 3 万行）只显示前面一部分：
    末尾有一行“已自动截断”的提示，标题栏的增删统计后面也会标出“（已截断）”。
- **离线**：远端分支、ahead/behind 全部来自本地已有的远端引用，ggit 不联网、不 fetch、不写任何 Git 数据。
  左上角的状态行显示“上次 fetch”时间。别的程序（比如 Antigravity）fetch 之后，在 ggit 里按 `F5` 就能看到新的远端分支。
- **自动刷新**：窗口重新被激活、或切换项目时，自动刷新当前项目。在别的程序里操作完仍没看到变化，按 `F5`。
- **编码**：默认逐行自动检测，先 UTF-8，失败再 GBK；“查看 → 文件编码”里可强制指定。
- **查看菜单**：可忽略空白差异、忽略换行符（CRLF/LF）差异。

## 配置文件

`%APPDATA%\ggit\config.json`（项目列表、当前项目、窗口位置、显示选项、diff 模式、字体大小）。

程序出现未处理的异常时，会弹出提示并把详细信息追加到同一目录下的 `crash.log`。

## 打包成单个 exe（可选）

```bat
pip install pyinstaller
pyinstaller --noconsole --onefile --name ggit --icon ggit/assets/ggit.ico ggit.pyw
```

程序图标内嵌在 `ggit/icon_data.py` 里，打包后不依赖外部图片。

## 重新生成图标（可选）

```bat
pip install pillow numpy
python tools/make_icon.py
```

输出 `ggit/assets/ggit.ico`（多尺寸）、`ggit/assets/ggit.png` 和内嵌用的 `ggit/icon_data.py`。

## 开发：测试与代码检查

```bat
pip install -r requirements-dev.txt
python tools/check.py
```

`tools/check.py` 依次运行三项检查，全部通过才算通过：

- **ruff**：代码风格和常见隐患（规则见 `pyproject.toml`）
- **mypy**：类型检查；核心层（`gitcore`、`cancel`、`graph`、`difftools`、`items`、`fileutil`、`config`、
  `options`、`utils`）要求每个函数都写类型注解
- **pytest**：核心层用真实的临时 Git 仓库测试；界面层的测试在 Qt 的 offscreen 平台上运行真实的窗口，
  只通过公开接口操作和检查。测试不会在桌面上弹出窗口、托盘图标或通知，不注册全局热键，
  读写的是临时配置文件，不会碰到 `%APPDATA%\ggit\config.json`

只想跑测试：`python -m pytest`（或不装 pytest：`python -m unittest discover -s tests`）。

`.github/workflows/ci.yml` 是 GitHub Actions 配置：推到 GitHub 后，每次推送都会在 Windows 上
用 Python 3.10（支持的最低版本）和 3.12 各跑一遍 `python tools/check.py`。

## 目录结构

```
ggit/
  —— 核心层（不依赖界面库）——
  gitcore.py         调用 git、解码（UTF-8/GBK）、解析 status / log / diff / 文件历史 / 分支列表
  cancel.py          取消后台 git 任务（gitcore 用它结束正在运行的子进程）
  graph.py           提交图的分支线布局算法
  difftools.py       diff 加工：裁剪成“只看改动处”、左右对照对齐、改动分段
  items.py           提交图列表条目（提交行 + 展开的文件行）
  fileutil.py        file 模式：读取文本文件做预览
  config.py          配置文件读写
  options.py         显示选项、字号范围
  utils.py           时间格式、有上限的缓存（LruCache）
  —— 界面层 ——
  ui_main.py         主窗口：顶部项目导航、菜单、托盘、全局热键、字体缩放
  ui_nav.py          顶部 200 宽的项目大标签（可拖动排序）
  ui_project.py      单个项目的页面：组装下面这些面板，负责刷新和它们之间的联动
  ui_status.py         左上角的状态行（分支按钮、同步徽标、上游与 fetch 时间）
  ui_branches.py       分支下拉列表（Ctrl+B）
  ui_changes.py        “更改”面板（未提交的文件）
  ui_graph_panel.py    “图形”面板：显示范围、分页加载、展开 / 收起提交
  ui_history.py        “文件历史”面板
  ui_graph.py        提交图列表（模型 + 自绘）
  ui_docs.py         文档标签页（每个文件一个标签，切换 / 关闭），以及文档视图的接口 DocView
  ui_diff.py         diff 视图（两种模式、加宽滚动条与色块、改动跳转）
  ui_files.py        file 模式：文件树、文件预览
  ui_dialogs.py      快速选择对话框（Ctrl+P / Ctrl+F）
  ui_common.py       各面板共用的小部件和 HTML 片段
  theme.py           深色主题：全部颜色和样式表（按控件 objectName 匹配）
  async_runner.py    后台线程执行 git，结果回到界面线程
  winhotkey.py       Windows 全局热键与“置顶显示”
  icon.py / icon_data.py   程序图标（内嵌）
tools/
  check.py           一条命令跑完 ruff + mypy + pytest
  make_icon.py       重新生成图标
tests/
  support.py         测试共用：offscreen 平台、临时配置文件、临时 Git 仓库、等待后台任务
pyproject.toml       ruff / mypy / pytest 的配置
requirements.txt     运行依赖；requirements-dev.txt：开发依赖
```
